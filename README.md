# Бронирование переговорных

Frontend для поиска и бронирования переговорных комнат. Backend из задания находится в `server`(без изменений) и используется как API и WebSocket-сервер.

## Запуск

Требуется Node.js 20+.

В первом терминале запустите API:

```bash
cd server
npm ci
cp .env.example .env
npm run dev
```

Во втором — клиент:

```bash
cd client
npm ci
cp .env.example .env
npm run dev
```

Откройте `http://localhost:5173`. API доступен на `http://localhost:3000`, документация API — на `http://localhost:3000/documentation`.

## Возможности

- список комнат с обязательным выбором офиса и фильтрами: дата, время, длительность, вместимость;
- расписание комнаты, создание и отмена собственных будущих бронирований;
- обработка конфликтов бронирования (`409`), loading/error/empty-состояния;
- real-time обновление расписания и доступности комнат;
- страницы `/rooms`, `/rooms/:roomId`, `/bookings`, редирект `/` → `/rooms` и 404.


## Проверки

```bash
cd client && npm test
cd client && npm run build
```

## Технологии и архитектура

- React, TypeScript, Vite, React Router;
- TanStack Query и Axios для запросов и кэша;
- WebSocket для обновлений в реальном времени;
- React Hook Form, date-fns и `@date-fns/tz` для форм и времени;
- Tailwind CSS, Base UI/shadcn;
- Vitest и Testing Library.

Клиент организован по FSD: `pages` собирают экраны, `widgets` — крупные блоки интерфейса, `features` — пользовательские сценарии, `entities` — данные предметной области, `shared` — общие API, UI и утилиты. Типы API сгенерированы из OpenAPI (`client/src/shared/api/schema/openapi.d.ts`).

## Принятые решения и дополнения

- **Таймзоны офисов.** Дата, рабочие часы, интервалы поиска и создаваемые брони рассчитываются в timezone выбранного офиса, затем передаются API в ISO UTC. Это исключает сдвиг времени у пользователей из другого часового пояса и на переходах летнего времени.
- **Фильтры в URL.** Офис, дата, время, длительность и вместимость хранятся в query-параметрах. Ссылкой можно поделиться, состояние сохраняется при обновлении страницы и проходит нормализацию невалидных значений.
- **Последний офис.** Выбранный офис дополнительно хранится в `localStorage`, чтобы не выбирать его заново при следующем визите.
- **Устойчивый real-time.** Реализованы reconnect с экспоненциальной задержкой, индикатор соединения и resync после подключения. События инвалидируют кэш комнат и бронирований, поэтому обновляется и открытое расписание, и список комнат.
- **Экспорт `.ics`.** Собственные бронирования выбранного дня можно скачать в формате календаря и импортировать в календарное приложение.
- **Повтор бронирования.** Из записи в расписании можно открыть форму с уже заполненными датой, временем, длительностью и текстом; новое бронирование всё равно проходит обычную валидацию и проверку API.
